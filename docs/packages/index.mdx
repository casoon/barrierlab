The crates sit in four layers. Dependencies only point down: a package never uses one from
its own or a higher layer. None of them opens a page or speaks a browser protocol — the data
comes from the tool that embeds the packages.

<Diagram name="crates" />

| Layer | Crate | Purpose |
|---|---|---|
| L0 | [`html5-parser`](https://docs.rs/html5-parser) | WHATWG HTML5 tokenizer and tree construction |
| L0 | [`csp-parse`](https://docs.rs/csp-parse) | Content Security Policy grammar |
| L0 | [`media-query-parse`](https://docs.rs/media-query-parse) | CSS Media Queries grammar |
| L0 | [`xpath-eval`](https://docs.rs/xpath-eval) | XPath 1.0, generic over the document model |
| L0 | [`relax-ng`](https://docs.rs/relax-ng) | read and validate RELAX NG schemas |
| L0 | [`schematron-engine`](https://docs.rs/schematron-engine) | ISO Schematron rules, XPath via `xpath-eval` |
| L1 | [`a11y-dom`](a11y-dom.md) | document model as a trait plus capability tiers |
| L1 | [`a11y-report`](a11y-report.md) | one finding and report model with stable JSON |
| L1 | [`stylesheet-parse`](stylesheet-parse.md) | CSS stylesheets with their `@media` context |
| L1 | [`html-conform`](html-conform.md) | HTML5 conformance, comparable to vnu, no JVM |
| L2 | [`accname`](accname.md) | accessible name and description per WAI-ARIA |
| L2 | [`a11y-rules`](a11y-rules.md) | the rule set, generic over the document model |
| L2 | [`a11y-perception`](a11y-perception.md) | perception over browser data: AX tree, reading order, diff of two snapshots |
| L2 | [`web-checks`](web-checks.md) | robots.txt, meta lengths, OpenGraph, JSON-LD, hreflang |
| L3 | [`a11y-wasm`](a11y-wasm.md) | the rule set as WebAssembly, on npm as `@casoon/a11y-wasm` |

All 15 are on crates.io. The four a11y crates `a11y-dom`, `a11y-report`, `accname` and
`a11y-rules` are versioned together; all others independently.
